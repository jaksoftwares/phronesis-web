PHRONESIS APPLICATION
Branding, Typography, Colour & UI Style Guidelines

Status: Foundation Specification
Version: 1.0
Product: Phronesis Homeschool Digital Platform

1. Design Direction

The application should feel:

Academic + Modern + Calm + Trustworthy + Human + Intelligent

The UI must not feel like a generic SaaS dashboard, nor like a children's gaming application.

The visual language should communicate:

Knowledge — academic credibility
Growth — learner development
Trust — reliability and institutional quality
Clarity — easy navigation and independent learning
Warmth — supportive learning environment
Progress — modern technology and forward movement
Core principle

The interface should get out of the learner's way and allow learning to remain the focus.

2. Brand-to-UI Relationship

The application should derive its visual language directly from the institutional identity:

PHRONESIS BRAND
       ↓
Logo & Emblem
       ↓
Colour System
       ↓
Typography
       ↓
Spacing & Grid
       ↓
Components
       ↓
Application UI

Do not allow individual application pages to develop their own visual styles.

3. Typography System
Primary Typeface — Inter

Inter should be the primary application typeface.

Use it for:

Navigation
Headings
Body text
Buttons
Forms
Tables
Dashboard content
Notifications
Labels
Data
Learning interfaces

It provides a clean, highly readable digital foundation.

Secondary Typeface — Source Serif 4

Use Source Serif 4 selectively.

It can be used for:

Educational introductions
Long-form learning material
Editorial sections
Institutional quotations
Selected learning content
Major statements

Do not use it throughout the dashboard.

The basic rule:

INTER
→ Application interface

SOURCE SERIF 4
→ Editorial / educational emphasis
4. Typography Weights

Use a controlled weight system:

400 — Regular
500 — Medium
600 — Semibold
700 — Bold

Avoid using dozens of font weights.

Recommended usage
Weight	Purpose
400	Body text
500	Labels / secondary emphasis
600	Navigation / component headings
700	Major headings
5. Application Type Scale

Recommended starting scale:

Display      48px / 56px
H1           36px / 44px
H2           30px / 38px
H3           24px / 32px
H4           20px / 28px
Body Large   18px / 28px
Body         16px / 24px
Body Small   14px / 20px
Caption      12px / 16px

On mobile, the scale should reduce responsively.

The default application body size should generally remain 16px.

7. Neutral Palette

Use neutral colours heavily.

Ink        #17212B
Slate      #52616B
Mist       #E9EEF2
Cloud      #F5F7F9
White      #FFFFFF

This creates visual breathing room.

The application should feel predominantly light, clean and spacious.

8. Semantic Colours

Brand colours and status colours should remain separate.

Define:

Success
Warning
Error
Information
Pending
Disabled

For example:

Success → Green family
Warning → Amber family
Error   → Red family
Info    → Blue family

Do not use Phronesis Gold to mean "warning" merely because it is yellow-ish.

9. Colour Usage Ratio

A good starting point:

60% — White / neutral surfaces
25% — Deep Blue
10% — Teal
5%  — Gold

This should keep the application professional.

10. Background System

Use multiple levels of surfaces:

Background
Surface
Surface Elevated
Surface Muted
Border

For example:

Application background → #F5F7F9
Cards                  → #FFFFFF
Primary text           → #17212B
Secondary text         → #52616B
Borders                → #E9EEF2

Avoid putting every card on a coloured background.

11. Buttons

Buttons should have a clear hierarchy.

Primary

Deep Blue background.

Used for:

Start learning
Book class
Submit
Save
Continue
Secondary

White/neutral surface with border.

Tertiary

Text-based action.

Destructive

Dedicated error/destructive colour.

Button principle

There should normally be one obvious primary action per section.

Avoid screens containing five equally prominent buttons.

12. Cards

Cards should be used to organize information—not simply because cards look modern.

Examples:

Subject card
Course card
Resource card
Upcoming class
Assessment
Progress summary
Teacher profile

Recommended:

Background: White
Border: subtle
Radius: 10–14px
Shadow: minimal
Padding: 16–24px

14. Dashboard Design

A dashboard should answer:

What do I need to know or do next?

Do not fill the dashboard with decorative statistics.

Learner dashboard priority
Welcome / current learning
        ↓
Continue Learning
        ↓
Upcoming Classes
        ↓
Recent Resources
        ↓
Assessments
        ↓
Progress

The learner's current educational activity should dominate.

15. Learning Interface

Learning pages should have fewer distractions than administrative screens.

Prioritize:

Lesson title
Learning objectives
Content
Video/animation
Examples
Activities
Exercises
Assessment
Next lesson

The interface should make the learning path obvious.

16. Progress Indicators

Progress should be visual but restrained.

Use:

Progress bars
Completion percentages
Milestones
Topic completion
Subject progress
Assessment history

Avoid turning the application into an excessive gamification system.

17. Subject Identity

Subjects can have secondary visual identifiers, but they should not create completely different design systems.

For example:

Mathematics
Integrated Science
English
Kiswahili
Social Studies
CRE
Pre-Technical Studies
French
German
Mandarin

Each can have a subtle icon or supporting colour.

However:

Phronesis remains the dominant brand.

18. Icons

Use one consistent icon family.

Recommended characteristics:

Simple
Professional
Geometric
Clear
Consistent stroke weight

Icons should support comprehension rather than decorate the interface.

19. Forms

Forms should prioritize clarity.

Every form should have:

Label
Input
Supporting text
Validation
Error state
Success state where relevant

Never rely solely on placeholder text as the field label.

23. Border Radius

Recommended:

Inputs        8px
Buttons       8px
Cards         12px
Large panels  14–16px

Keep the system consistent.

24. Shadows

Use subtle elevation:

Level 0 → No shadow
Level 1 → Very subtle
Level 2 → Card/modal elevation
Level 3 → Dialog/popover

The UI should not look like every component is floating.

25. Responsive Design

The application must be designed:

Mobile-first.

Then progressively enhanced for:

Mobile
Tablet
Laptop
Desktop
Large desktop

The experience should not simply be a desktop interface squeezed onto a phone.

26. Accessibility

Target:

WCAG 2.2 AA

Design and engineering should enforce:

Adequate contrast
Keyboard navigation
Visible focus states
Screen-reader support
Proper labels
Accessible forms
Touch-friendly controls
Captions for educational videos
Alt text where appropriate
27. Low-Bandwidth Design

This is especially important for Phronesis.

The interface should work well when:

Internet is slow
Video is unavailable
Images are still loading
Connection temporarily drops

Use:

Skeleton loading
Optimized images
Lazy loading
Progressive content loading
Clear offline/error states
Resumable video where technically supported
28. UI States

Every major component should have defined states.

For example:

Default
Hover
Focus
Active
Selected
Disabled
Loading
Success
Error
Empty

This should be part of the design system—not implemented differently by each developer.

29. Empty States

Empty states should be useful.

Instead of:

"No data."

Use:

No classes scheduled yet.
Your upcoming virtual classes will appear here once they are scheduled.

The interface should explain what happens next.

30. Error States

Errors should be:

Clear
Human-readable
Specific
Actionable

Avoid technical messages such as:

HTTP 500 INTERNAL SERVER ERROR

in the learner experience.

Technical information can remain available to administrators/developers.

31. Loading States

Avoid blank screens.

Use:

Skeletons
Progress indicators
Loading labels where appropriate

The user should understand that the system is working.

32. Educational Content UI

Learning content should have its own refined presentation layer.

For example:

Subject
   ↓
Strand
   ↓
Topic
   ↓
Learning Objective
   ↓
Lesson
   ↓
Practice
   ↓
Assessment

This hierarchy should be visually obvious.

33. Premium Content

Premium resources can use the Knowledge Gold accent for identification.

But don't turn the interface into a marketplace.

A small:

PREMIUM

badge is sufficient.

34. Logo Placement in the Application

The logo should generally appear:

Desktop

Top-left/navigation area.

Mobile

Compact mark or simplified logo.

Login

More prominent institutional identity.

Learning content

Small, restrained watermark/header.

Certificates

Full institutional identity.

Avoid placing large logos everywhere.

35. UI Design Principle

A very important rule for the development team:

Brand consistency does not mean every page should look identical.

The:

Public Website

should feel welcoming.

The:

Learner Portal

should feel focused.

The:

Teacher Portal

should feel professional.

The:

Admin Portal

should feel operational and information-rich.

Yet all four should clearly belong to Phronesis.
